# Design decisions

Brief record of decisions and why. Dated when recorded here (2026-10-27) unless noted.

- **Pipe files only (2026-10-27).** Station RX/TX pipe fields name `modems/<file>` only. No shell commands, no absolute paths. Reason: a station file or recording someone hands you must not be able to run an arbitrary program. Custom commands are wrapped into a pipe file in `modems.d` after the user confirms the exact contents. Load migrates known absolute paths in memory; anything else is disabled with a visible warning.
- **Asset-kind registry.** Allowed asset folders come from `hsrec::safepath::KINDS` (today only `MODEMS`: `modems/`, `.rxpipe`/`.txpipe`, user folder `modems.d`). A new kind (e.g. flowgraphs) is one more entry. Resolver rejects absolute paths, `..`, subfolders, symlinks, non-owner-executable files, and group/world-writable files or folders.
- **Release builds never search the CWD or source tree** for assets. Debug builds also search the source `modems/` and `HAMSPOT_DEV_MODEMS`.
- **Decoder settings are generic.** Recordings carry `decoder_params`, a free-form `HAMSPOT_[A-Z0-9_]+` map; replay passes them as env vars. Keys outside the pattern, and values that look like paths, are refused from data (`--param` on the CLI can still set them). Reason: future decoders can save what they need without schema changes.
- **No WACN/SYS/NAC in the station file.** Learned from the air. `dsd-fme -X` is the site word, not a key.
- **Keys live in `Name.HSKeys` (0600)**, never in the station JSON.
- **Commander starts and stops its own `rigctld`/`gqrx`/`rotctld`/`ampctld`**; it never attaches to ones it didn't start.
- **Amplifiers:** never sent Operate on load or restart; patch bay is visual only; boxes bind to the amplifier's fixed random id, never its name. Antenna switching, PTT/ALC and automatic operate are not planned without a separate decision.
- **Layout reference:** the Tune face loosely follows the Ham Radio Deluxe 5.21 rig screen (behaviour only; no icons, bitmaps or text copied).
- **Data layout (proposal, not built):** `Foo.HSCommander` plus a `Foo.HSData/` folder; see `docs/design/data-layout.md` on branch `design-data-layout` and epic #148.
- **Manual style (2026-10-27):** operator-only content, second person, tables for reference, screenshot placeholders as HTML comments with #149 ids.

## E-STOP button height (#200, 2026-10-27)

The E-STOP and RELEASE buttons use the standard egui button height
(`estop::button_height` = `max(interact_size.y, button text + 2 * button_padding.y)`,
the rule `egui::Button` uses) and the Button text style. Width follows the text.
The octagon radius is about half the text height, kept 2 px clear of the border.
The fixed 24 px `BUTTON_H` is gone, and the Config E-STOP group bars went back from
28 px (r_out 16) to the normal 16 px (r_out 12) `Metrics::default()`. The tan top bar
and the Tools tab row were not enlarged for it.

## HF data decode window (#217)

- Code lives in `crates/commander/src/hfdata/`. One **HF Data** page (not one window per decoder) with mode toggles; a tabbed or per-decoder split can come later.
- Plug-in point: `registry::DecodeMode` (turns one decoder stdout line into a `Decode`) plus a `Factory` registered with `Registry::register`. `Session` drains an `mpsc::Receiver<String>` of decoder lines into the shared `DecodeList`. The rxpipe/patch bay wiring that feeds that channel belongs to the first mode issue (#206) and #171/#172.
- `registry::parse_wsjt_line` parses `HHMMSS SNR DT FREQ ~ MSG`; time of day is resolved to the latest instant not in the future (midnight rollover). Rows stamped more than 2 s ahead are refused and counted on screen.
- Slots count from the Unix epoch; lengths must divide a UTC day (`SlotLen::new`).
- Clock check: `chronyc -c tracking`, then `timedatectl`, on a thread once a minute. Warn above 1.0 s, when unsynchronised, or when neither answers.
- Presets: `share/hfdata/presets.json` (embedded, `deny_unknown_fields`, no paths). All `checked: false`. Several common dials sit in the ARRL plan's CW segments (e.g. FT8 7.074, FT4 7.0475, WSPR 7.0386); the page states the segment rather than hiding it.

- **VNA device scans (#219, 2026-10-27).** Scans of patch-panel devices go in `Foo.HSData/VNA/<device uid>/<UTC stamp>[-n].HSVNAScan`, derived from the station file name (first use of `Foo.HSData/`, #148; the planned `vna/` for calibration is separate). Devices gain a random `uid` (assigned once, also to older devices at load). Scan files hold no paths. Kinds beyond the original seven are data: `crates/commander/src/vna_devices/rf_kinds.json` (ports, left/right side, scan plan `s11|all_pairs|all_ordered|from_first`, TX through-paths, `tx` flag); a new row needs a rebuild but no code. All ports are 50 Ω. The wizard reuses the calibration wizard's step style and wiring painter (`paint_device_wiring`), not the calibration `Wizard` state itself.
- **Format change: `HSVNAScan` v1 (#219, for #203).** JSON `{format:"HSVNAScan", version:1, device_uid, device_name, device_kind, ports, taken_at, start_hz, stop_hz, points, vna_id, cal_note, by, note?, length_m?, vf?, steps:[{step:{ch0,ch1?,loads?}, raw: StoredScan, corrected?: StoredScan}]}`. Newer/unknown versions are refused and left untouched. Written temp + hard link (never overwrites). `serde_json` now has `float_roundtrip` so sweep values survive a load/save exactly. Station file: patch `Device` gains `uid`, `rf`, `nports`, `notes`, `length_m`, `vf` (all optional; older Commanders refuse these files because `Device` is `deny_unknown_fields`). Marker `Foo.HSData/VNA/tx-lockout.json` `{format:"HSVNALock",version:1,device,since}` exists only while a lockout-holding scan runs.
- **TX lockout (#219).** `tx_lockout::TxLockout` is a set of named holds; transmit is allowed only when none remain. Refusal sites: `App::ptt` (PTT/MOX, with text), `App::send` backstop for `SetPtt(true)`, `App::send_amp` for `SetPower(Operate)`. The VNA hold is engaged before the sweep is requested, released on finish or cancel, made manual (Release button only) on disconnect, and restored as manual at station load when the marker is left over. **E-Stop (#198) convergence:** E-Stop should add its own hold key at the same three sites (and its rotator stop path); it stays separate in behaviour (latched, manual release) and must not be cleared by the VNA release.
- **E-Stop + TX lockout converged (merge to main, 2026-10-27).** Implemented as `tx_lockout::refuse_transmit(lock, estop::engaged(), action)` at the three App sites (`App::ptt` PTT/MOX, `App::send` for `SetPtt(true)`, `App::send_amp` for OPERATE/On). E-Stop is checked first and gives "… refused. E-STOP is engaged; press RELEASE …"; otherwise any lockout hold gives "… refused. TX LOCKOUT: …". E-Stop was not turned into a lockout hold key: it keeps its own latched state, persisted file and device-hub choke points (`estop::allows_rig/allows_amp/allows_rot`, TX pipe stop, rotator stop), so the rotator is covered by E-Stop at the hub only (the lockout never held the rotator). VNA "Release TX lockout" cannot clear E-Stop and RELEASE cannot clear a VNA hold. Test: `tx_lockout::tests::transmit_is_refused_under_estop_or_lockout_with_its_own_text`.

## E-STOP button shape, second fix (#200, 2026-10-27)

David rejected the first #200 fix on screen (E-STOP ~30 px with big text, RELEASE ~24 px, both rounded). Real cause: E-STOP drew its text with `TextStyle::Button` (rustcars `apply_theme` sets it to Antonio 22 pt, galley 28 px → 36.5 px button), while RELEASE was an `egui::Button`, which in egui 0.37 draws a `&str`/`RichText` label with `FontSelection::Default` = **Body** (15 pt, galley 19 px → 19 + 2 × 4 = 27 px), so the two never matched. Rounding came from E-STOP's own `rect_filled(rect, 4.0, …)` and, for RELEASE, egui's widget visuals (`corner_radius = 4` from rustcars `apply_theme`, which every other app button also uses).
Now: `estop::std_button_font` / `std_button_height` reproduce what `ui.button` really uses; one `square_button` paints both buttons (corner radius 0 `estop::CORNER`, 1.5 px border in both states, same font); `estop::buttons` lays them out with `horizontal_centered` so they sit centred in whatever bar slot they get. Headless tests (`estop::tests`) run a themed `egui::Context` frame and assert E-STOP, RELEASE and a plain `ui.button` are all 27 px and that the buttons are centred in a 44 px bar. The other app buttons were left rounded.

## Tools detach is the page pill (#221, 2026-10-30)

The square tear-off tab at the right of the page row and the deferred `hamspot-tools` viewport are gone. Tools now detach like Config, REC, Timers, HF Data, Levels and Keys: the top-right page pill (`DETACHABLE_PAGES`, `detached_window`, an immediate viewport). The detached window shows E-STOP / RELEASE at the right of its top row and then the same body as the page (tool sub-tabs, status line, tool screen); it polls the E-STOP chord itself.
**Migration:** the eframe storage keys `tool_detach` ("1"/"0"), `tool_win_pos` and `tool_win_size` ("x,y") are read once at startup by `migrate_tool_detach` into the Tools page `DetachState` (detached, pos, size). `Tools.detached` / `saved_pos` / `saved_size` mirror that state every frame and the same three keys keep being written, so the setting survives restarts (other page pills do not persist) and an older build still reads a sensible value. `Tools.dock` is gone (closing the old window set it). Test: `tool_detach_migrates_to_the_page_pill`.

## Meters detach is the page pill (#221, 2026-10-30)

The Meters **Detach** / **Dock** buttons and the deferred `hamspot-meters` viewport (with its `MeterFeed` snapshot copy) are gone. Meters detach with the top-right page pill like the other detachable pages; the detached window draws the same meter page from the live snapshot (immediate viewport, so it repaints with the main window).
**Migration:** `MeterState.seed_pill` is set when the meter state is loaded, at startup from eframe storage (`meter_detach`, `meter_win_pos`, `meter_win_size`) and on station load from the station file's `meters.detached` / `meters.window`. On the next frame `seed_meter_pill` copies it into the Meters page `DetachState`. After that the pill is the source and `MeterState.detached` / `saved_pos` / `saved_size` mirror it every frame, so the storage keys and the station file format are unchanged (no file format change). The detached window still records `monitor_*` and `pixels_per_point` for the station file. `MeterState.dock` is gone. Test: `meter_detach_seeds_the_page_pill`; the existing `a_torn_off_meter_window_round_trips_and_an_old_file_stays_locked` still covers the file.


## Config sections and the Rotator page (page layout 2, 2026-10-30)

David: Keys and Levels become sections of Config; Rotator leaves Tools and becomes a top page tab beside Tune / Channels / TG.
- **Keys / Levels** are two more Config groups (`CONFIG_GROUPS`, `cfg_group`), after RF patch, contents unchanged (`page_keys`, `page_levels`). Config's sections are its detachable groups, so a detached Keys or Levels is now a detached Config group; the old page detach states were session-only (egui temp data), so nothing to migrate there. `Page::Keys` / `Page::Levels` stay as internal variants (not tabs, not detachable).
- **Rotator** is `Page::Rotator` (after Channels in `PAGES`; TG / ID tabs still insert after Channels), detachable, drawn by `Tools::draw_rotator_in` in the shared page frame; its bar asks only for the AZ / EL LEDs (`tools::rotator_bar_width`), no tool tabs. `Screen::Rotator` stays internal; it is not in `SCREENS`.
- **Migration:** the station file has `page_layout` (`PAGE_LAYOUT` = 2, written always; absent reads 0). Loading a layout-0 file maps `page` Keys / Levels to Config (`migrate_page_name`), drops Keys / Levels from `tabs` and places Rotator after Channels (`migrate_tabs`), and puts a line in the Config note saying so (never silent). An older Commander refuses a layout-2 file (`deny_unknown_fields`); staging builds only.
- Tests: `config_sections_tests::*`, `page_layout_round_trips_and_defaults_to_zero`.

## Rotator world map (2026-10-30)

David: optional azimuthal-equidistant map behind the Rotator rose.
- Projection written directly in `tools/rotator/map.rs` (great-circle bearing -> rose angle via `geom::dial_xy`, angular distance -> radius); no projection crate, no native deps. Edge = antipode (π) or a range of 100…20015 km.
- Data: Natural Earth 1:110m coastline, public domain, as `crates/commander/data/coastline-110m.txt` (header `# hamspot coastline v1`), `include_str!` so the binary is portable (no paths), parsed once (`OnceLock`), re-projected only when centre/range change (`MapCache`). Lines split where they leave the edge or jump > 0.35 disc units (antipode wrap).
- Setting: `Settings.map` (`MapSettings { version: 1, show: false, lat, lon, range_km }`) inside the existing eframe-storage `rotator_settings` JSON, `serde(default)` so old JSON loads with the map off, and older builds ignore the field. Text is kept as typed; a bad value or data error is appended to the Rotator status line as `MAP OFF: …` (never silent).
- No station location exists in Commander yet, so there is no default centre; lat/lon must be typed. When a station location is added it should seed blank fields.
- Tests: `tools::rotator::map::tests::*`, `tools::rotator::tests::map_draws_faint_behind_the_rose_docked_and_small`, `bad_map_input_is_reported_not_silent`.

## GPU-safe rendering default (2026-10-30)

Report: on Tower5810 (3 AMD GPUs: W5000 01:00.0 = renderD128, W5100 02:00.0 = renderD129, W5000 03:00.0 = renderD130) video playback in other apps stopped while Commander ran and resumed when it closed; an amdgpu sdma1 timeout + reset on 03:00.0 at 18:07 EDT followed a monitor hotplug.
- **From code (confirmed):** Commander's renderer is eframe glow (OpenGL via glutin/EGL); `Renderer::default()` is Glow when the `glow` feature is on. The eframe `default` features (pulled in by Commander and rustcars) also compiled wgpu/Vulkan (ash, gpu-allocator) into the binary, unused. Nothing in Commander or glutin calls EGL device enumeration.
- **Measured on the box:** `eglinfo -p wayland` opens only renderD128 with GPU rendering, and no render node with `LIBGL_ALWAYS_SOFTWARE=1` (llvmpipe). Why Commander held renderD129/130 is **inferred, not proven**: Mesa's Wayland EGL opening the scanout GPU's node (PRIME/dmabuf feedback) for windows on monitors driven by the other cards.
- **Change:** eframe `default-features = false` + `glow` in Commander and rustcars (f0ffc2b), so wgpu/Vulkan are no longer built. `render.rs`: `RenderSettings { version: 1, mode: Auto|Gpu|Software }` in `<eframe data dir>/render.json`; `HAMSPOT_SOFTWARE_RENDER=1/0` overrides for one run; Auto = software when more than one `/dev/dri/renderD*`. Software sets `LIBGL_ALWAYS_SOFTWARE=1`, `GALLIUM_DRIVER=llvmpipe` first thing in `main` (no threads yet). The choice, reason and the actual `GL_RENDERER` are printed at start and shown under Config > Display, with a warning if software did not take (never silent).
- **Repaint throttle:** the vendored eframe 40 ms overdue-redraw retry now applies only to a window with a visible detached child; other unseen windows use upstream's 250 ms.
- Not changed: HackRF capture (8 Msps DDC + 15/s FFT on the CPU) and its 15/s repaint are the likely main CPU cost; out of scope here.

## Spectrum redraws only when shown (2026-10-30)

David: "work on the redraws when tuning is not visible". Each HackRF spectrum frame (~15/s, `SpecPump`) made `cat::publish_spectrum` call `request_repaint`, so the whole UI was laid out and drawn 15×/s on every page (with software rendering now the multi-GPU default, that is CPU). Now `Hub::spectrum_watched` (set each UI pass from `redraw::spectrum_wanted`) gates that repaint: wanted = a scan is on, or a detached window shows spectrum data, or the selected page does (Tune, Talkgroups, RadioIds; `page_shows_spectrum`) and the main window is not minimized. Frames are still stored every time (`store_spectrum`), and capture start/stop always repaints. Untouched: hackrf_transfer reading, DDC, voice/control demod, REC taps/raw IQ, the FFT (one 1024-point FFT 15×/s, negligible, and the scanner and TG RSSI read it). No new setting. Unchanged and still repainting: CAT snapshot publishes for rig-polled radios, meter needle animation while moving, NanoVNA device wakes. Pre-existing, not changed: a memory scan advances in the UI pass, so with the main window minimized and no detached window it still only steps on the 250 ms overdue logic passes.

## Rotator map fill (2026-10-30)

David: "fill the interior of the map polygons? black for water and dark blue for land". Data switched from 1:110m coastlines to 1:110m land polygons (`data/land-110m.txt`, `# hamspot land v1`, 64 KB; the coastline file is removed and coasts are drawn from the land rings minus the data's artificial ±180° / -90° edges). Fill: each polygon (with holes) is triangulated once in lon/lat with the `earcut` crate (0.4.11, MIT OR Apache-2.0, only dep num-traits), then split until every side is ≤ 10° of arc (10,536 triangles). Per centre/range (cached in `MapCache`) each triangle is projected; triangles crossing the map edge are split (depth 4) and clamped to the circle at the last level, those near the antipode (within 0.15 rad) are split and dropped at the rim, so nothing tears across the disc. World view ≈ 10.5–12.6 k triangles, a 2000 km range ≈ 2.5 k; drawn as one mesh. Ocean = black disc (`OCEAN_COLOR`), land `LAND_COLOR` #12265A, both under the elevation globe; coasts and rings over it, rose on top. No setting change.
- Follow-up (David, "globe should be see through when a map is loaded"): when the map is drawn (`MapCache::get` succeeded), `horizon::paint(.., see_through = true)` skips the globe's GROUND disc and SKY polygon; horizon line, ladder + labels, meridians, rim, wings, preset marker and OFF flag are unchanged. Map off or invalid: globe unchanged. Test: `map_draws_faint_behind_the_rose_docked_and_small` (no ground/sky fill after the land mesh; with the map off both are present).

David (annotated screenshot): sub VFO under the main VFO, remove the Fine bar, remove the text above the digits; then the BSP rows overlapped the keys.

## Tune gain fields (2026-10-30)

LNA/VGA on the Tune SPECTRUM · GAIN row use `tune_style::gain_slider` instead of `egui::Slider` inside a rounded inset: one `KEY_H` row, square, 1 px border (trace colour on hover/focus), 11 px caption and value, 2 px track, 4x12 square handle. The track is 40-112 px and shrinks to the column width before clipping. Behaviour is the same: drag/click sets, wheel steps (handled by the caller as before), arrow keys step while focused, and the commit happens on drag stop / wheel / key. `tune_style::inset` removed (it was only used here). Other `egui::Slider`s (rotator speed, Config 1-10, audio/filter sliders) are unchanged.
